# Changelog

Each release is tagged on `main`. Dates are in US Central time.

## Unreleased

- Members see what REDCap would show them. A REDCap table maps member ids to REDCap usernames in `[tables.<id>.redcap_users]`, and each `data_query` reads that user's row from the project's user export before any record: an unmapped member, a run with no member, a username the project lacks and an expired user are refused, and so is a column on a form the user may not export, or a date or free-text field under de-identified rights. The records export asks only for the record id and the query's fields, and for a user in a Data Access Group the engine drops every other group's rows before it counts. The record keeps the rights that applied, and a rerun under changed rights says so. The fake REDCap serves `content=user` and `content=dag` and honours `fields` and `exportDataAccessGroups`; `pnpm walk:data` shows two members getting 12 and 30 to the same question. A REDCap table with no `redcap_users` now refuses every query: add the map before upgrading.
- `aliquot audit export [--since <seq|time>] [--follow]` prints the audit stream and every run record as JSON lines for syslog or a SIEM forwarder: ids, data classes, hashes, actors, refusal codes and payload references, never a question, an answer, a changelog or a URL's path. Lines come out in commit order (migration 0009 stamps an `export_seq` on both tables under one lock), so a forwarder that resumes with `--since <last seq>` misses nothing. The line format is version 1 and [`docs/install.md`](docs/install.md), "Logging and monitoring", documents it.
- `GET /healthz` on the web door answers 200 when Postgres answers and a worker beat within 30 seconds (`?max_age=` sets it), else 503. Workers beat a new `worker_heartbeats` table every 5 seconds and remove their row when they stop. It needs no token.
- The studio signs in to Postgres as its own role, `aliquot_studio`, which owns the `studio` schema and is refused every core table (`payloads` and `web_messages` included). Migration 0011 creates it when core's user is a superuser, as in the compose stack; the web door sets its password from `ALIQUOT_STUDIO_DB_PASSWORD` as a SCRAM verifier. `aliquot init` writes the password into a new `.env`; an existing install adds `ALIQUOT_STUDIO_DB_PASSWORD=$(openssl rand -hex 24)` to `.env` before upgrading. `scripts/restore.sh` creates the role before restoring onto a new server. `scripts/compose-check.sh` checks all three on the running stack, and `ALIQUOT_CHECK_PROJECT` renames its Compose project.
- Accessibility, checked on every `pnpm unit2`: axe-core 4.14.0 (a pinned test-only dependency) scans the chat page, a run record, the runs list and the studio's agent and knowledge base forms in light and dark, and any serious or critical WCAG 2.1 A or AA violation fails the run. A keyboard-only walk asks a question, hears the answer, checks and opens its record and downloads the JSON, asserting a focus ring of at least 2 px and 3:1 at each of its nine stops in both themes. The chat page announces each new answer or refusal once through one live region, instead of reading out everything the thread adds, and the question field's focus ring is now 5.5:1 instead of about 1.6:1. The studio repairs Payload's own markup that failed seven axe rules (unnamed icon buttons and drag handles, select inputs without labels, hidden icons in the tab order, help text and Add row at 2.8:1). [`docs/accessibility.md`](docs/accessibility.md) states what is tested, the result and the known exceptions, and the README links it.
- A usage ledger a grant can be charged from. `[prices.<model or endpoint>]` in `lab.toml` sets a rate per million tokens in and out, with a currency and an effective date; `[[prices.<id>]]` with a later date is a rate change, and each call is priced at the rate in force when it was made, in exact arithmetic rounded once per total. An agent's new optional **Project** field (a grant number or cost center, set in the studio) is stamped on each run's `run.started`, so the charge follows the project in force when the run happened; it is governance, so it never changes a version hash. `aliquot usage --from --to --by agent|project|member|endpoint [--csv|--json]` totals runs, calls, tokens and cost from the run records alone, checks each run's hash chain (exit 3 when one is broken), and prints "no price" for a call with no rate instead of zero. `--by member` groups by the member id on each run's trigger. The record page and `aliquot record` show the run's cost when prices exist. The studio gains a Payload migration for the field. `pnpm lab0` gains check U, which prints the synthetic lab's usage line and checks it against the records.
- Answers from the lab's data. A data steward registers a CSV or a REDCap project in `lab.toml` as `[tables.<id>]`, marks each column free or restricted (an unnamed column is restricted, and a field REDCap flags as an identifier always is), and sets `aggregate_class` and `min_cell` (5 or more). An agent lists table ids in `tables` and holds the new `data_query` tool: the model writes a query of filters, group-by columns and counts, sums, means or standard deviations; the harness refuses a restricted column before reading the table; the rows are computed on in the sandbox container; and any group or measure under the minimum cell size refuses the whole query. Only the aggregate reaches the model. Each record holds the query, the table's sha256, the engine's hash and the numbers, so a reviewer can rerun it. `pnpm walk:data` shows a member asking lab0's visits CSV and REDCap project (`scripts/fake-redcap.ts`) three questions; `docs/for-research-it-and-irb.md` gains "Minimum cell size".
- Document sources. `[sources.<id>]` in `lab.toml` registers a Box, OneDrive or Google Drive desktop sync folder (`kind = "folder"`, with a `scope`) or a Google Drive folder through the Drive API (`kind = "gdrive"`, scope from each file's permissions) as the source of a knowledge base. `kb sync` ingests them; `kb sync --watch` re-ingests a folder on every change and polls Drive, and publishes a new snapshot only when a document's text changed. Each entry carries its source, file, version (an HMAC of its text) and modified time. `kb_search` and `kb_read` show the model the version, the run record names every document version a run read, `GET /runs/:id/sources` compares them with the current documents, and the chat page says **Changed since this answer** under an answer whose cited document was edited since. Entries carry a scope (`lab`, `member:<id>`, `group:<name>`), enforced at retrieval: a member outside it never has the entry in the outline, in search (whose ranking ignores it) or in a read. `[directory]` maps members to groups and Drive emails to members until sign-on lands. `pnpm walk:sources` walks the loop; `pnpm lab0` gains check K. [`docs/sources.md`](docs/sources.md).
- Data bound to named people and a date. A `[duas.<id>]` table in `lab.toml` records a data use agreement: the `members` it names (the member id every run records, the `[auth]` `id_claim` under sign-on), the last day it holds (`expires`), its data `class`, and the `knowledge_bases`, `entries` (`<kbId>/<path>`) and `datasets` it covers. Every knowledge base read and dataset a run's tools see goes through the asking member's DUAs: for a member a DUA does not name, for a run no member started, and for everyone once it expires, its entries leave the outline, `kb_search` and `kb_read`, and its datasets leave `dataset_list` and `run_code`, and the tool output names the DUA and the rule. A member it names reads its data at its class's level; asking an agent on a hosted model whose knowledge base holds DUA data is refused at the door with zero model requests, naming the DUA, and recorded as `gate.refused`. `lab.toml` refuses a DUA in a class a hosted model reads (NIH NOT-OD-25-081), a DUA that covers nothing, one item under two DUAs, and a dataset declared below its DUA's class level. `pnpm walk:dua` walks two members through it on lab0 and checks every request each model received; `test/dua-wire.test.ts` holds the same checks in the suite. The chat's Source chip reopens a cited DUA entry only while the DUA still admits the run's member, so a source stops opening the day after its DUA expires.
- Signing out ends the session everywhere. Web door sessions now live in a `door_sessions` table (migration 0008) holding the member, how the role was decided, created, last seen, and when and why it ended; the signed cookie carries only a random session id, and the table only its sha256. **Sign out** ends the session on the server, so a copy of the cookie in another browser stops working. A session idle past `idle_timeout_minutes` or past its 12 hours is ended on the server too, a removed studio account ends every session of that member on the next request, and a session whose role came from `roles_claim` lasts `[auth] claim_role_max_minutes` (default 60) before the member signs in again and the provider names the groups afresh. Last seen is written at most once a minute. Sessions signed in before this release end, and members sign in once more. `pnpm walk:signon` gains a step: B signs out in one browser and the copied cookie in another is sent to sign in.
- One channel can hold several agents, and the router picks the one a question is for. Publish two agents whose `channels` name the same channel and intake routes each message between them: the lexical router (`router.ts`, BM25 over each agent's name, description and sample questions, a description's "Not for" sentence left out) runs in the door with no model, so it routes a restricted message without sending it anywhere. Options are published, routable agents open to the member whose ceiling admits the message's class. When the top agent is under 0.75 the member picks: the chat page shows the agents by name with one line each, picked by click, tap, the arrow keys or the number, and Slack posts a numbered list answered by a mention with the number or the name. The pick sends the same message again to that agent, and later questions in the thread stay with it. The decision (agent, why, every option's score, `lexical-v1`) is in `run.started`, and the record page shows it as **Routed to**. A channel with one agent runs it as before. `pnpm lab0` check R publishes a methods agent beside the handbook on one channel; `pnpm walk:router` walks a member through it and saves stills of the chat page.
- Anchors: records a database admin cannot quietly rewrite. The audit stream and run records were hash-chained in Postgres, but anyone with write access could change a row and recompute every later hash, and `verify` passed. With `[anchor] path` in `lab.toml` and `LABH_ANCHOR_KEY_FILE` naming an Ed25519 key, the worker signs the head (seq, hash) of the audit stream and of every run closed since the last anchor, every `every_minutes` (default 15), and appends one line to that file. `aliquot anchor` writes one by hand and prints it on stdout, so research IT can forward each line to write-once storage or the SIEM; Aliquot makes no network call for it. `aliquot verify` recomputes every chain, and `--anchors` also checks each line's signature and place in the log and that the database still holds each signed hash, naming the first seq that changed and when (exit 3). It reports a forged line, a line under another key and a removed line. `aliquot init --anchor-key <file>` writes a new key (mode 600, never over an existing one) and the `[anchor]` table. A worker with `[anchor]` set and no key or no `--allow-fs-write` for the log refuses to start. `pnpm lab0` ends with check Z: a worker-written anchor over every run, verified.
- Microsoft Teams: `aliquot teams` answers a mention in a channel or group chat, or a message in a personal chat, through the web door as a new `[surfaces.teams]` (kind `teams`), with the same refusals, the same record link and the same thread behaviour as Slack. Teams posts to the bot, so the door listens on `/api/messages` behind the lab's TLS proxy and reads only activities the Bot Framework signed for the lab's app, from the lab's tenant, naming a Teams connector host; anything else is a 401 and asks nothing. A teams surface may be `institution` at most, because Microsoft keeps every message in the tenant. `docker compose --profile teams up -d` runs it; [`docs/teams.md`](docs/teams.md) has the app manifest and the steps a campus Teams admin follows, and the app asks for no Microsoft Graph permissions. `pnpm demo --teams` runs it against a stand-in for Teams and prints the thread, and `pnpm lab0` gains check T: a cited answer in the channel thread with a record link that opens, and a participant id refused with zero hosted requests.
- Payload keys by id. `lab.toml` can name keys in `[store.keys]` (`k1 = "LABH_PAYLOAD_KEY"`, `k2 = "LABH_PAYLOAD_KEY_2"`) with `[store] current`; `key_env` alone still works and means `k1`. New payloads go under the current key, each stored payload is read with the key whose id it carries, and `aliquot keys reencrypt` moves old payloads to the current key in batches that each commit, so it resumes and a second run does nothing. Payload hashes never change: the address key is the lab's for life, kept wrapped under each key in a new `payload_keys` table (migration 0005), and a process refuses to start, naming the key id, when any key it holds does not match the key the lab knows by that id. Key env var names must be names (`^[A-Z_][A-Z0-9_]*$`), and the backup scripts compare them as strings. `aliquot keys status` prints each key, its env var, whether this process holds it, how many payloads it holds and how many wait to move; `aliquot keys rotate` records the rotation in the audit stream. `docs/install.md` has "Rotate the key".
- Per-class keys. `[store.class_keys]` (for example `D3 = "k3"`) puts a class under its own key. A web door or worker that is not given that key lists those bodies on the record page as unavailable, under `k3`, and the chain still verifies. The record page and `aliquot record` gain a Bodies table: each body's hash, class, size and whether it is stored, unavailable here or redacted, never its text.
- Retention. `[policy.retention]` sets `keep_min_days` (the floor the lab's records rules set) and `purge_payload_after_days` lab-wide or per class; a purge shorter than its class's floor refuses to start. `aliquot retention --dry-run` lists each run past the window and changes nothing; `--apply` deletes those bodies, keeps a tombstone (hash, class, size, when, why), clears the web door's plaintext copy of the reply, checks every chain it touched and writes a `retention.swept` audit event. The record page shows "Redacted on <date> by the lab's retention window" with the hash. `--dry-run --as-of` previews a later date; `--apply` refuses `--as-of`. The same body put again after a sweep (a question asked again) fills the tombstoned row under the current key, so the run answers. `docs/install.md` has "Retention", and the IRB doc's key and retention lines now say what a lab can configure.
- `scripts/backup.sh` carries every payload key that holds bodies (`payload-key`, `key-ids`) and refuses, naming the id, when one is missing from `.env`. `scripts/restore.sh` refuses a backup whose keys are not all supplied and names the missing id; a backup from before key ids restores as before. `compose.yaml` passes `LABH_PAYLOAD_KEY_2` and `LABH_PAYLOAD_KEY_3` to the worker and the web door, and still none to the studio.
- `pnpm walk:keys` walks a steward through rotation, re-encryption, a D3 key, a reader without it, and a retention sweep on a synthetic lab, with a PASS line per step.
- University sign-on on the web door. An `[auth]` table in `lab.toml` names an OpenID Connect provider (issuer, client id, `client_secret_env`, `session_secret_env`, `email_claim`); members sign in at `/login` with the authorization code flow and PKCE, the door verifies the ID token with `node:crypto` (RS256, RS384, RS512, ES256, ES384) against the provider's published keys, and keeps a signed, HttpOnly, SameSite=Lax session cookie for 12 hours, which ends sooner after `idle_timeout_minutes` unused (30 by default; HIPAA automatic logoff): a page then goes back through `/login`, and JSON answers 401. The member id every run records is the provider's stable id (`id_claim`, `sub` by default, `eppn` for CILogon with `scopes` adding `org.cilogon.userinfo`), and the record page's first line names it. The role comes from a group or entitlement claim when `roles_claim` and `[auth.roles]` map one, else from the studio account with the token's email, read on every request; someone with neither is told to ask the PI. An email decides a role only when the provider says it verified it (`email_verified` true), unless `trust_unverified_email` is set; `email_claim` refuses `preferred_username`, `upn` and `unique_name` without it. Signed in, the door ignores a `user` in a request body, `/runs` lists the runs the member asked signed in (the data steward and the PI see all), and another member's record, events, view, sources, replies and stop answer 404. A token surface's run is never a member's own, and a token surface reads and lists only its own surface's runs. `next` after sign-in must resolve to the door itself, the callback shows a fixed message for a provider error, and `/logout` is POST only. Without `[auth]` the door behaves as before. `packages/core/src/surfaces/signon-wire.ts` is the one new file allowed the network, to reach the provider. `test/fake-oidc.ts` is a local provider for tests and walks.
- `[surfaces.web] bind` sets where the door listens. Beyond loopback, `lab.toml` and the binary both refuse it without `[auth]`; compose passes `LABH_BIND` to the door as `--published`, so publishing the door off the machine needs sign-on too.

Every study write is in the audit stream with the OS user beside the self-declared `--as`, and migration `0006_freezes_guard.sql` stops a freeze row being rewritten or deleted.

- Campus presets: a reviewer sees Aliquot's data classes in the campus's own words. `preset = "uw-madison"`, `"umich"` or `"harvard"` in `lab.toml` loads `presets/<id>.toml`, which maps UW-504's Public, Internal, Sensitive and Restricted, Michigan's Low, Moderate, High and Restricted, or Harvard's five data security levels (Sensitive from Level 3) onto the classes, and adds the classes each campus needs. A message carrying PHI (a span in the lab's `phi` class, an MRN, a date of birth, any HIPAA identifier detector, or a `PHI` banner at the start of a line) is refused at any hosted endpoint without `baa = true`, and export-controlled or CUI content (a span in the `export_controlled` or `cui` class, or an `ITAR`, `EXPORT CONTROLLED` or `CUI` banner) at any hosted endpoint whose region is not `us`, with no request sent. - `pnpm review-pack [--config path]` writes a security review pack for a lab: `docs/review/<lab>/hipaa.md`, `nist-800-171.md`, `hecvat-answers.md` and `summary.md` (counts per status, not met first). The controls live in `packages/core/src/review/controls.ts`: HIPAA 164.308(a)(1) and (a)(5), 164.310(d), 164.312(a) to (e) and 164.316(b)(2); every NIST SP 800-171 Rev. 3 family, at the requirement level where Aliquot has a mechanism; and the HECVAT 4 areas for data, application security, authentication, AI, privacy, accessibility and incident response, paraphrased. - Data classes are a policy a lab declares. `[classes.<id>]` in `lab.toml` names a class's `model_tier` (`hosted`, `local` or `none`), what the record keeps of a refused message (`record`: text, hash or nothing), `retention_days`, an optional `residency` country, its `detectors` and the `message` a member reads. New detectors cover the HIPAA Safe Harbor identifiers a pattern can find (`hipaa-safe-harbor` names them all), a DUA marker for controlled-access data (`DUA:` lines, dbGaP `phs` accessions, EGA ids) and export-control markings. A class whose tier is `none` is refused at the door before a run exists, with zero model requests, and recorded in the audit stream as `gate.refused`; a knowledge base source in it is refused before the compiler is called (`kb.source-refused`). A class with `residency = "us"` is read only by an endpoint with `region = "us"`. - `pnpm trust` measures what a lab, an IRB and research IT ask first, and writes the numbers with their date and commit to [`docs/trust.md`](docs/trust.md): how often an answer holds a claim its entries do not support, cites the wrong entry, refuses what it should answer, answers what it should refuse, and obeys an instruction planted in a document. It runs a new synthetic lab, `fixtures/lab1` (234 entries, 350 questions with ground truth, 44 planted instructions in SOP and PDF text), through the real run loop with a scripted model that obeys every planted instruction, in about a second and without Postgres or a key. `pnpm trust --live` asks Sonnet the same prompts through `claude-batch` and checks each claim of each answer. A `trust` CI job runs the deterministic part on every push and fails when a count gets worse than `docs/trust.json`.
- Fix: a tool's refused network request no longer ends the run as refused. When a model called a literature tool from a run that had read lab documents, the egress decision rightly refused the request, but the run then ended with "it contains restricted data" on a question it could answer. The model now reads the refusal as a failed tool call and answers without the tool; nothing is sent either way. On lab1 this took answerable questions refused from 20 to 7 and answers lost to a planted instruction from 10 to 0. `aliquot ask` and `aliquot acp` no longer report such a run as refused.

- The studio holds no payload key. Every read and write it made of core's state goes to the web door's new `/studio` routes with the token of a new `[surfaces.studio]` (kind `studio`): KB compiles (the door reads the sources and stores them encrypted, then queues the worker job), compile results, KB and agent publishes, test messages, test-run replies, and an entry preview for authors that never shows a D3 entry. Each route checks the member's role and the data's class in the door. Test threads now run on the `studio` surface, so their run keys and record pages say `studio`. `compose.yaml` gives the studio its own environment with `ALIQUOT_STUDIO_TOKEN` and `LABH_DOOR_URL` and no `LABH_PAYLOAD_KEY`, and `scripts/compose-check.sh` asserts it. `aliquot init` writes `[surfaces.studio]` and the token. An existing lab adds the table from `lab.example.toml` and `ALIQUOT_STUDIO_TOKEN=$(openssl rand -hex 32)` to `.env`; without them the studio says what is missing. `test/boundaries.test.ts` fails when anything the studio loads reads the key.

## 0.5.0 (2026-11-03)

- One `docker compose up` on Linux starts Postgres, the worker, the web door and a production build of the studio. The studio applies committed Payload migrations at start, and CI fails when the collections change without one. Ports are published on `127.0.0.1` unless `.env` sets `LABH_BIND`. [`docs/install.md`](docs/install.md) is the guide for research IT.
- PDF sources for knowledge bases, from the `kb` command. poppler reads them inside the sandbox container (no network, read-only root, uid 65534), never in a Node process. A page that is only an image fails the whole file with a message naming the page, because Aliquot does no OCR. `compose.sandbox.yaml` gives the Docker socket to the worker only. The studio gets no socket, so PDFs compile with the `kb` command.
- `aliquot init` (`pnpm aliquot:init`, or `docker compose run --rm init` on a machine with only Docker) writes `config/lab.toml` and `.env`. It tests the lab's participant id patterns against ids you paste, with a PASS or FAIL line for each, refuses a pattern that matches ordinary words, and never rewrites an existing `.env`.
- `scripts/backup.sh` and `scripts/restore.sh` back up and restore the database and the payload key. Restore refuses a key the backup was not made with, and ends by checking every run's hash chain.
- `scripts/compose-check.sh` runs all of it on a machine with only Docker, and CI runs it on a clean Ubuntu runner: a cited answer from the lab0 handbook, a LaTeX PDF and a Word PDF read in the sandbox, a scanned page that must fail, then a backup, wipe and restore that ends with the same run verifying and decrypting again.
- The web door takes `--host`, so it can listen inside a container. The `kb` command prints a source it cannot read as one line instead of a stack trace.
