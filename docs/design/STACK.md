# Stack decisions

How facts were checked, on 2026-10-22:
- **npm**: `npm view <pkg> name version license repository.url` against the public registry.
- **GitHub API**: `gh api repos/<owner>/<repo>` for license and last push; `gh search code` for source facts.
- **Docs**: fetched the vendor's docs page and read the relevant section.
- **Search**: one web search result summary. Weaker than the others.

Anything else is marked **unverified**.

| Decision | Pick | Runner-up | Deciding reason |
|---|---|---|---|
| Language and runtime | TypeScript on Node 22 LTS, for core and studio. One language in the repo. | Python 3.12 (Django admin for the studio, Slack Bolt plus a Teams SDK) | The two libraries that save the most rounds only exist in TS: Chat SDK, with Slack, Teams and Gmail adapters and a Postgres state adapter, and Payload CMS. Lab members write documents and skills, not core code. Their R and Python run in the sandbox, written by agents. |
| Durable execution | **Our own journal on Postgres.** One `jobs` table (idempotent key, `SKIP LOCKED` claim, lease epoch) plus `run_events` (fenced append, hash chain). The run record is the history. About 500 lines. | DBOS Transact TS: MIT and pushed 2026-10-22 (GitHub API). Postgres-only operation is from memory and **unverified** this session. | With DBOS, step outputs live in its tables and again in our run record. That means two copies of D3 data with two retention rules, or a run record that reads DBOS internals. It would also impose workflow determinism rules on contributors. A fold over events needs neither. Also considered: **Absurd** (Apache-2.0, GitHub API; describes itself as "An experiment in durability"; a production report from April 2026 came from search only). It has the same two-copies problem and is less mature. **Temporal self-hosted** is a separate server with its own history store, so it fails the one-dependency rule. **Vercel Workflow DevKit Postgres world**: not checked, **unverified**. **pg-boss and Graphile Worker** are queues only, so we would still write the journal, and the claim query is the easy part. Their licenses are **unverified**. |
| Document store and studio | **Payload CMS 3.92.0** (MIT) with `@payloadcms/db-postgres` (MIT), both from npm. Versions with diff and restore work with drafts disabled (Payload versions docs). Payload holds drafts and revisions. Core holds published heads and immutable versions. | A custom form app on Postgres | Non-developer authoring quality is the HCI bet, and forms, revisions, diff, restore and roles for three document types would cost two or more rounds to build. **Directus** is rejected: its license file is the "Monospace Sustainable Core License" (MSCL-1.0-GPL), read from the repo header only. It is not a standard OSI license, which is a poor fit as a hard dependency of an open-source lab tool. **Sanity Studio** is rejected because its content store is hosted (spec 3.2; **unverified** this session). Payload auth with university SAML or OIDC is **unverified**. |
| Chat front door | **Vercel Chat SDK** `chat` 4.43.0 (MIT) with `@chat-adapter/slack`, `@chat-adapter/teams` and `@chat-adapter/state-pg`, all 4.43.0 (npm search plus the package README). `@chat-adapter/gmail` exists for email-in later. The web page is our own route in the app. | Slack Bolt plus Microsoft's Teams SDK used directly. Maintenance status is **unverified**. | One abstraction covers both required platforms, and its state adapter runs on Postgres, so we still need only app plus Postgres. Sanity used it, so we know it works for this exact use. Streaming and stop-affordance support per adapter is **unverified**. Its dedupe overlaps our job key; our key is the source of truth. |
| Model gateway | **Our own OpenAI-compatible client** over `fetch`, with SSE streaming. One wire protocol for OpenRouter, Ollama, vLLM and institution servers. About 300 lines. | Vercel AI SDK `ai` 7.0.150 (Apache-2.0, npm) | The gateway is the egress choke point, and it must compare the returned model id and send OpenRouter's `provider` fields. We checked those fields in OpenRouter's provider-routing docs: `zdr: true`, `data_collection: "deny"`, `allow_fallbacks: false` and `only`. Owning the client also keeps frozen-study behavior independent of an SDK on its seventh major version. Vision and other non-chat modalities would favor the AI SDK later. Anthropic or Google models through their native APIs (not OpenRouter) are **unverified** on the compatible endpoints. |
| Router backend | A **`logprob-choice`** classifier on any OpenAI-compatible endpoint that returns logprobs. Local by default (Ollama's OpenAI-compatible layer returns logprobs, per `gh search code` in `ollama/ollama` `openai/openai.go`). A **`decision-api`** adapter for a hosted decision model comes in P2. | Embedding similarity with a softmax | Logprobs over option labels give real per-option probabilities on lab hardware, so D3 traffic can be routed. Embeddings give similarity, not a calibrated choice. The Jev wire format and OpenAI's Decisions API are **unverified**. Logprob support through OpenRouter varies by provider and is **unverified**. Thresholds are calibrated per backend. |
| KB compile and BM25 | **Our own `bm25-v1`**, in process, built on first use per immutable snapshot and cached. Snapshot manifests and entry bodies live in Postgres (`kb_snapshots` and `payloads`). Compile is a `kb-compile` job through the gateway. | ParadeDB `pg_search` extension (license and packaging **unverified**) or Postgres FTS (`ts_rank` is not BM25, from memory and **unverified**) | No Postgres extension for department IT to install. Rankings are reproducible because we own the scorer and its version is in the frozen hash. Lab KBs have hundreds to low thousands of entries, so building the index in memory is cheap. That size claim is an estimate, not measured. |
| Sandbox for R and Python | **One container per call through the Docker Engine API** over the unix socket, using `node:http` and no client library. The image (R plus Python) is pinned by digest. `--network none`, read-only mounts from the steward's allowlist up to the agent's mount ceiling, a per-thread workspace volume, and CPU, memory and time caps. Optional gVisor `runsc` on Linux servers. | bubblewrap or nsjail directly | Docker works the same on a lab Linux box and a macOS laptop, so `docker compose up` holds. Linux-only namespaces do not. Giving the worker the Docker socket is root-equivalent, and whether rootless Docker or Podman fixes that for IT review is **unverified**. Every sandbox fact in this row is **unverified** this session. |
| Small libraries | `pg` 8.23.1 (MIT), `zod` 4.6.7 (MIT), `smol-toml` 1.9.1 (BSD-3-Clause), `croner` 10.0.1 (MIT). All from npm. | Hand-rolled equivalents | Each replaces more code than a few lines of the standard library would. Encryption (AES-256-GCM), sha256 and canonical JSON use `node:crypto` plus our own code. |
| Observability | **SQL views over `run_events`.** An OpenTelemetry export projection comes in P2. | A separate metrics store | Derived, never synced. OpenTelemetry's generative-AI conventions are **unverified**. |
| Identity | University sign-on into a `members` table, linked to chat platform user ids on first web login. | Per-platform identities only | The protocol (SAML via Shibboleth or OIDC) depends on the pilot lab. Library choice is **unverified** and open. |

Runtime dependency count for `@labh/core`: 8 packages (see `packages/core/package.json`). The studio adds Payload and its Next.js stack, quarantined in `packages/studio`.
